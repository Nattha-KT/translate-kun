# Rust, distributed as a single native binary

`kun` is a CLI invoked many times a day and it handles Provider API keys, so startup time, binary size, and safe native credential storage matter more than raw development speed. Rust gives a ~5–10 MB binary with near-instant startup and a cross-platform OS-keychain crate, and the author wants to learn it. Future Adapters (e.g. a VS Code extension) integrate by calling `kun --json` rather than importing the core, so the CLI's JSON output is a public contract.

## Considered Options

- **TypeScript + Bun** (initially chosen, then reversed before any code was written): fastest to build and would let a TypeScript VS Code Adapter import the core directly, but ~50–60 MB binaries, slower startup, and shelling out to `security` for the keychain. Rejected once it was clear the VS Code Adapter works fine over `--json`.
- **Go**: small and fast, but no learning goal attached and a weaker fit than Rust for the author.

## Consequences

- The author is new to Rust, so v1 will take longer; keep the design simple (avoid clever lifetimes/async where not needed).
- `--json` output must be versioned and kept stable, because Adapters depend on it.
