# S8 — Release: cargo-dist, Homebrew tap, crates.io, verifiable artefacts

## Background

The repository is public at `github.com/machngai/translate-kun`, and `main` is protected by a ruleset (PR plus required checks). The owner approved the first release, **0.1.0**, through these channels:

- **GitHub Releases:** prebuilt archives built by `cargo-dist`.
- **Homebrew tap:** `machngai/homebrew-tap`, so users run `brew install machngai/tap/kun`.
- **crates.io:** `cargo install translate-kun`. The library is `translate-kun-core`. Both names are free.
- **No shell or PowerShell installer** (`curl | sh`) for now. The owner decided this explicitly.

Requirements: `docs/requirements.md` §10 (prebuilt binaries for macOS and Linux, Windows best-effort, Homebrew tap, `cargo install`).

This slice only **prepares** the release. Nothing is tagged or published here. After merge, the owner pushes a release candidate tag `v0.1.0-rc.1` to exercise the whole pipeline as a GitHub pre-release, then `v0.1.0`.

## Tasks

1. **cargo-dist setup.** Install the current release of cargo-dist with `cargo install cargo-dist --locked`; the binary may be called `dist` or `cargo dist`. Report the version. Run init non-interactively with the settings below, then run `dist plan` (or `cargo dist plan`) and report its output.
   - **Targets:**
     - `aarch64-apple-darwin`
     - `x86_64-apple-darwin`
     - `x86_64-unknown-linux-gnu`
     - `aarch64-unknown-linux-gnu`
     - `x86_64-pc-windows-msvc`
   - **Archives and checksums:** default archive formats (`.tar.xz` for Unix, `.zip` for Windows) and **sha256** checksums.
   - **Installers:** `homebrew` **only**. Tap `machngai/homebrew-tap`, `publish-jobs = ["homebrew"]`, formula name `kun`. The tap token secret is `HOMEBREW_TAP_TOKEN`; use that name if cargo-dist lets you choose it.
   - **Supply chain:**
     - `github-attestations = true`: build provenance attestations.
     - `cargo-auditable = true`: dependency list embedded in the binary.
     - `cargo-cyclonedx = true`: SBOM.
   - **Pre-releases:** must not publish to Homebrew; this is the cargo-dist default, so keep it.
   - **`pr-run-mode = "plan"`.**
   - **Only the `translate-kun` package (binary `kun`) is distributed.** `translate-kun-core` is a library: it goes to crates.io only and must not produce a release artefact.
   - **Third-party licences:** produce a `THIRD-PARTY-LICENSES` file (HTML or Markdown) with `cargo-about`, and include it in every archive alongside `LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE` and `README.md`. Use cargo-dist's own mechanism (for example `include` plus a build step or extra-artifacts) if it has one; otherwise add the smallest custom step and explain it. The accepted licences in `about.toml` must match the allow-list in `deny.toml`.
2. **Pin the release workflow's actions by SHA**, as in S15 and S16.
   - Prefer cargo-dist's own setting for pinned action commits if your version has one (check its docs or `dist init --help`).
   - Otherwise pin by hand, set `allow-dirty = ["ci"]`, and document in `docs/development/releasing.md` that the release workflow is hand-maintained after generation.
   - Resolve every SHA with `git ls-remote` or `gh api`. Never guess one.
   - Keep `permissions` minimal per job: `contents: write` only where the release is created; `id-token: write` and `attestations: write` only on the attestation job.
3. **`publish-crates.yml`.**
   - Triggered when a GitHub Release is **published** and is **not a pre-release**, plus `workflow_dispatch`.
   - Uses **crates.io Trusted Publishing** through the official `rust-lang/crates-io-auth-action`, SHA-pinned.
   - Permissions: `id-token: write` and `contents: read`.
   - Publishes `translate-kun-core` first, then `translate-kun`, and skips a crate whose version is already on crates.io, so a rerun is safe.
   - No long-lived token anywhere.
4. **Make both crates publishable.**
   - `cargo publish --dry-run -p translate-kun-core` must pass, and so must `cargo package -p translate-kun --list`. `translate-kun` depends on an unpublished `translate-kun-core`, so its dry run may fail; report that rather than working around it.
   - Check that the licence files (symlinked into each crate) end up in the package as real files, and that no test fixture, fuzz corpus or doc that is not needed is shipped. Use `include` or `exclude`.
5. **Docs.**
   - **`README.md`, "Install" section:**
     - `brew install machngai/tap/kun`
     - `cargo install translate-kun`
     - Download from GitHub Releases.
     - A short "Verify your download" subsection: `gh attestation verify <file> -R machngai/translate-kun`, plus a `sha256sum -c` / `shasum -a 256 -c` example.
   - **`SECURITY.md`:** add the same verification steps under "Security assurance", and mention the SBOM and `cargo audit bin` for checking an installed binary.
   - **`docs/development/releasing.md` (new):** a step-by-step maintainer checklist:
     1. One-time setup by the owner:
        - Create the `machngai/homebrew-tap` repository (public, empty, with a README).
        - Create a fine-grained personal access token whose only access is **Contents: read and write** on `machngai/homebrew-tap`, with a sensible expiry, and save it as the `HOMEBREW_TAP_TOKEN` repository secret on `translate-kun`.
        - Log in to crates.io with GitHub and turn on 2FA.
        - **Publish the first versions manually** (`cargo publish -p translate-kun-core`, then `-p translate-kun`), because Trusted Publishing can only be configured on a crate that already exists.
        - Configure Trusted Publishing on crates.io for both crates (repository `machngai/translate-kun`, workflow `publish-crates.yml`).
        - Set up SSH commit and tag signing.
        - Add a tag ruleset for `v*` that blocks deletion and force-push.
     2. Every release:
        - Move the CHANGELOG entries from Unreleased to the new version, and bump the version in `Cargo.toml`, in a PR.
        - Merge it, then `git tag -s vX.Y.Z` and `git push origin vX.Y.Z`.
        - Watch the release workflow.
        - Verify the artefacts.
     3. The release-candidate flow: tag `v0.1.0-rc.1`, which creates a GitHub pre-release with no Homebrew and no crates.io publish.
   - **`CONTRIBUTING.md`:** one line linking to `releasing.md`.
   - **`CHANGELOG.md`:** add the release tooling under Unreleased → Added. Do **not** cut the 0.1.0 section; the release PR does that.
   - **`docs/development/slices/README.md`:** set S8 to "in review".
6. **CI stays green.**
   - The Definition of Done passes.
   - The existing CI jobs are unaffected.
   - `typos` and `machete` still pass.
   - The new workflows are valid YAML.
