## Scope and method

**Scope:** the whole repository at the commit above: the `kun-core` library, the `kun` CLI Adapter, the configuration and trust rules, the Secret Guard, the Provider code, the CI workflow and the dependency policy. The threat model is the one in [SECURITY.md](../../SECURITY.md): stop credentials and the user's text from leaking to third parties, logs, terminal output, shell history and other local users. Malware running as the same user, a hostile OS, debugger or memory access and timing side channels are out of scope.

**Method:**

- Manual reading of the source, with attention to every place a credential or the user's text is handled, formatted or sent.
- The test suite (364 tests passed) and `cargo deny check` (advisories, bans, licenses and sources all ok).
- More than 40 black-box probes against the built binary using the offline fake Provider, including hostile config files, odd inputs and error paths.
- A random fuzz run of about 300,000 inputs through the Secret Guard scan and redact, and Protected Terms protect and restore. It found no panic. (This was a one-off run. Repeatable fuzzing now lives in [`fuzz/`](../../fuzz) and runs weekly in CI.)
- A search of the git history for real-looking secrets, local paths, `.env` files and key files.

**Limits of the method:** one AI model, one pass, one commit. No live Provider calls, no penetration test of a real deployment, no review of third-party crates beyond what `cargo deny` checks, and no formal verification. An AI auditor can miss things that a human expert would find, and can report things that are not real.

## Areas verified as sound

- **Credentials.** The `Secret` type prints `<redacted>` and is not `Clone`. Keychain errors map to fixed categories. Lookup order is environment, keychain, then a `0600` file. There is no API key flag. Typed values are not echoed in argument errors. The fake Provider is behind a non-default feature.
- **User Config.** File permissions are checked on the same open handle that is read (no check-then-use race). A mode other than `0600` drops `[credentials]` and warns. TOML parse errors are dropped because they quote the source line.
- **Project Config trust (ADR 0003).** The forbidden-key check runs on the generic table, recursing into tables and arrays, case-insensitively, and held against inline tables, dotted keys and quoted keys. A Project Config can never supply credentials, an endpoint or `allow_secrets`, and can only make the Secret Guard stricter. A `.kun.toml` symlinked to a User Config is a hard error that does not leak a value. Very deep nesting does not crash.
- **Network.** TLS through `rustls` with default certificate verification (no custom or disabled checks, no OpenSSL). Redirects are disabled. The key goes in a header, never a URL. Response bodies are capped. Network errors map to fixed messages and HTTP error bodies are not kept. Proxies use `CONNECT`, so TLS is end to end. There is no logger, and the `log` level is capped so a dependency's TRACE output (which includes headers) is compiled out.
- **Secret Guard flow.** It runs before the Provider is built. Protected Terms are applied after it and only remove text. An unknown decision blocks. A bad extra pattern is a configuration error (fail closed). Piped input never prompts. The prompt reads the terminal and defaults to "no". Findings store only a kind and a byte range. The `regex` crate runs in linear time.
- **Panics.** Every string slice in non-test code lands on a character boundary. Input with Thai, emoji, backslashes, newlines and PEM fragments caused no panic. Stdin is size-capped and non-UTF-8 input is a usage error.
- **`kun init`.** It creates files without following symlinks, and `--force` replaces through a temporary file and rename.
- **Anthropic prompt.** `style` and the text are XML-escaped data in the user message, and the system prompt contains only validated language codes. The impact of prompt injection is limited to the output text.
- **Supply chain.** `cargo deny` passes and runs in CI. Dependabot covers Cargo and Actions. CI uses read-only permissions.
- **History.** No real-looking secret, local path, `.env` file or key file in any commit. Test fixtures are split and contain `FAKE` or `EXAMPLE`.

## Known limits (accepted)

- Windows is best-effort. There is no ACL check there, so `0600` is not enforced.
- A group- or world-writable `~/.config/kun` directory is not checked.
- Credentials are not wiped from memory. Memory scraping is out of scope.
- A very large `.kun.toml`, `max_chars` or `protected_terms` list can slow down your own machine. It is not a security boundary.
- The Secret Guard is pattern-based. It can miss a secret of an unusual shape and it can flag a harmless string. It is a safety net, not a guarantee.
- `kun-core` does not enforce the Secret Guard. Every Adapter must call it before any Provider call. See [architecture.md](../architecture.md).
